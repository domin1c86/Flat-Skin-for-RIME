# 扁平灰白 · 元书输入法自定义皮肤

这款皮肤以 iPhone 为主要使用场景，提供浅色／深色、竖屏／横屏的中文、英文、数字和符号界面。整体采用浅灰底板、白色字符键、灰色功能键和蓝色回车；深色模式对应炭黑底板与灰色键帽。

**皮肤负责外观，也可以定义按键动作和切换入口；真正的拼音转换、英文词库、候选与联想由元书和 RIME 输入方案负责。** 本皮肤不包含薄荷方案或英文词库，导入皮肤不会替你安装或修改输入方案。

## 这款皮肤有哪些特别的设计

- **独立中英文键盘。** 中文普通字母键面与气泡保持大写，英文普通气泡跟随键面大小写；两份主键盘各自拥有完整的符号动作，加载时无需等待语言通知补齐。
- **中英符号明确对应。** 字母键的上标、上滑气泡、上滑输入和长按符号项使用同一映射。例如 F 中文为 `＃`、英文为 `#`；H/J 中文为 `“`/`”`、英文两键均为 `"`。Q–P 的数字均保持半角 `1–0`。底行逗号、句号点按分别输入 `，`/`。` 或 `,`/`.`。
- **长按三选气泡。** 每个字母键可选择大写字母、对应上标和小写字母；默认选择符号或数字。气泡有柔和阴影、圆角和边缘适配，靠两侧的排序会镜像调整。
- **中英按钮同时选择布局与方案。** 英文使用独立英文方案，不只是让中文方案开启 ASCII 直通；工具栏的方案面板也会同步选择布局。
- **让候选成为显示重点。** iPhone 拼音预编辑字号为 12pt，候选字为 16pt；中文逗号句号按视觉中心调整，中／英图标的激活颜色一致。
- **统一键帽与分类样式。** 8.5pt 圆角、平面键帽，无立体底边；符号分类的选中背景有圆角与内缩，A/L 使用稳定的可视区域。

iPad 普通布局与分体保留原有行为，浮动键盘复用 iPhone 配置；本轮独立英文符号功能以 iPhone 和浮动键盘为目标。

## 安装与第一次使用

1. 先确认后文列出的中文、英文方案已经在元书中安装并启用。
2. 将 `扁平灰白.cskin` 通过文件或分享菜单用元书打开，导入后启用该皮肤；更新版本时重新导入并启用。
3. 打开普通文本输入框，使用本皮肤的中英按钮或方案面板选择目标方案。
4. 先试中文候选、英文单词候选，再检查 F/H/J 的上滑、长按以及逗号句号。配置和网页验证已通过，元书实机验收仍需按实际使用结果完成。

## 中英如何切换，各自使用什么方案

点击底行的「中／英」按钮即可切换，当前语言在图标中突出显示。

| 当前状态与操作 | 切换后的布局 | 切换后的输入方案 | 输入方式 |
| --- | --- | --- | --- |
| 中文状态，点击中英按钮 | 英文键盘 alphabetic | Easy English Nano，`melt_eng` | 普通字母交给英文词库生成候选 |
| 英文状态，点击中英按钮 | 中文键盘 pinyin | 小鹤双拼－薄荷定制，`double_pinyin_flypy` | 普通字母按小鹤双拼编码输入中文 |

**英文返回中文固定选择小鹤双拼，不自动记忆之前的其他中文方案。** 即使先选了薄荷全拼，切到英文后再点中英按钮，仍会回到小鹤双拼。要继续使用全拼，请从工具栏方案面板重新选择。

需要选择其他方案时，点击工具栏最右侧的循环箭头图标：

| 面板选项 | 方案 ID | 对应布局 |
| --- | --- | --- |
| 小鹤双拼－薄荷定制 | `double_pinyin_flypy` | 中文 |
| 薄荷拼音－全拼输入 | `rime_mint` | 中文 |
| 薄荷拼音－小鹤混输 | `rime_mint_flypy` | 中文 |
| Easy English Nano | `melt_eng` | 英文 |

面板是皮肤内预先配置的四个选项，不会扫描手机已安装的方案，也不会下载词库；取消选择会返回原键盘。对应方案必须已经安装并启用。

通过元书应用或原生菜单单独更换方案／ASCII 状态时，不保证同步切换这份皮肤的布局。发生错配时，使用皮肤自己的中英按钮或方案面板重新选择。

## 点按、上滑与长按怎么用

| 操作 | 用法与结果 |
| --- | --- |
| 中文普通点按字母 | 进入拼音／双拼候选；键面的大写外观不表示普通点按会直接输入大写英文 |
| 英文普通点按字母 | 输入当前大小写的字母并交给英文方案；有候选时可点击候选上屏 |
| 英文 Shift | 手动选择大写；普通气泡跟随键面。一次大写或锁定的实际保持方式由元书的 Shift 状态决定 |
| 上滑字母键 | 输入键面顶部的符号或数字；Shift 不改变这个符号 |
| 长按字母键 | 打开三选气泡，左右移动高亮，松手输入选中项；不移动时默认输入符号或数字 |
| 长按选择字母 | 直接输入固定大写／小写字母，不进入中文拼音或英文单词候选 |
| 空格 | 没有预编辑时输入空格；有预编辑时沿用候选选定行为，键面可显示「选定」 |

三选气泡通常从左到右为「大写／符号／小写」。靠左时改为「符号／大写／小写」，靠右时为「小写／大写／符号」；选中的符号格与按键对齐。进入长按气泡后，本次触摸应由气泡滑选处理，不再同时执行普通上滑；边缘位置、远移取消和手势互斥仍需实机确认。

网页预览按住 300ms 打开气泡，这是演示值，**不代表元书原生长按也已设置为 300ms**。长按网格以元书商店版 ≥1.6.27 为目标，保留旧版单行列表回退。

## 工具栏、数字页与符号页

主工具栏从左到右为菜单、留白、符号、Emoji、剪贴板、方案选择。菜单、Emoji 和剪贴板使用元书原生功能；主界面没有脚本和收起按钮，数字／符号页仍保留原有入口。

- 底行「123」打开数字九宫格；数字页「返回」使用返回主键盘动作，应回到进入前的中文或英文主键盘。
- 底行或工具栏的「符号」打开符号页；左侧切换常用／中文／英文分类。常用页有意混合中英文符号；分类不是由主键盘语言自动筛选的。
- 符号页锁定后可连续输入；「返回」使用返回上一键盘动作，从数字页进入时应回到数字页。实际返回行为需实机验收。
- Emoji 保留元书原生页面。皮肤没有强制进入笑脸分类的已核实参数；如果先看到历史记录，打开后手动点击底部笑脸分类。

## 皮肤与输入法分别负责什么

| 项目 | 由谁负责 |
| --- | --- |
| 配色、布局、圆角、图标、键面与气泡显示、皮肤中的字号参数 | 皮肤 |
| 上滑／长按绑定的字符、切页、布局与方案选择入口 | 皮肤定义动作，元书执行 |
| 中文转换、英文词库与单词补全、候选内容、自造词 | 元书／RIME 与当前输入方案 |
| 原生长按触发时间、自动句首大写、Shift 状态保持、成对符号、双击空格句号 | 元书的输入行为及其实际支持的设置 |
| 拼音／双拼的音节分隔和预编辑字符串格式 | 输入方案 |

皮肤已经绑定的字符可以直接上屏，也能选择输入方案；因此它不只是静态外观。但它不能凭空增加词库、预测引擎或元书未提供的设置能力。

## 本地预览、构建与检查

`default/` 是皮肤源码与生成配置，`preview/index.html` 可离线打开，提供三种风格对照；选择「体验扁平灰白」可操作点按、上滑、长按和方案选择。网页没有 RIME 或真实词库，不能验证实际中文／英文候选。

需要 Python 3.10+ 和 Jsonnet CLI；绘制示意图额外需要 Pillow。Jsonnet 可放在 PATH 或 `.tools/jsonnet.exe`。

```shell
python scripts/sync_preview_symbols.py
python scripts/build_skin.py --compile-only
python -m unittest discover -s tests -v
python scripts/render_skin_preview.py
python scripts/render_callout_preview.py
python scripts/render_hold_preview.py --language-states
python scripts/build_skin.py
python scripts/audit_letter_symbols.py
```

构建输出 `dist/扁平灰白.cskin`，目前包含 28 份键盘配置。符号映射位于 `default/jsonnet/Constants/LetterSymbols.json`，默认中文和英文方案位于 `default/jsonnet/Constants/InputRoutes.json`；修改后同步离线预览、重新编译和打包。仅修改说明时，重新打包即可，不需要改键盘配置。

查看 [逐键核对报告](docs/中英文符号核对报告.md)、[修复前记录](docs/中英文符号核对报告-修复前.md)和[实机验收清单](docs/中英文键盘实机验收.md)。当前配置与网页检查已通过，元书 1.11.0(558) 的最小实机验收仍待完成。

## 最后：需要在元书输入法中准备或调整的内容

以下以你提供的元书 1.11.0(558) 设置截图为参考。已经正常工作的项目不需要重复修改；原生菜单名称与可用选项以本机版本为准。

### 1. 必须准备：中文与英文方案

至少安装并启用 `double_pinyin_flypy` 和 `melt_eng`；要使用面板中的全拼、混输选项，再启用 `rime_mint`、`rime_mint_flypy`。

进入元书「输入方案」，通过右上角「⋯ → 方案列表编辑」检查启用列表。确认「方案目录切换」选中实际使用的薄荷目录；此目录是输入方案目录，不是皮肤目录。

找不到 Easy English Nano 时，先在「文件管理 → 应用文件 → RimeUserData → 当前薄荷方案目录」检查 `melt_eng.schema.yaml`、`melt_eng.dict.yaml` 及其引用的词库文件。完整薄荷包包含英文方案，但启用列表未必包含它；文件缺失时需导入包含依赖的完整方案包，不能只放一个 schema 文件。

文件齐全而列表中未启用时，可在同目录 `default.custom.yaml` 的现有 `patch` 中加入：

```yaml
patch:
  schema_list/+:
    - schema: melt_eng
```

仅在列表没有此项时追加；已有 `patch` 要合并，不能新建第二个同名节点，也不要覆盖已有中文方案列表。若文件已经显式定义 `schema_list`，可直接向该列表追加 `- schema: melt_eng`。保存后在元书执行「重新部署」，再检查方案列表和实际键盘。

### 2. 必须确认：英文候选与 ASCII 状态

通过皮肤按钮切到英文后，实际方案应为 `melt_eng`，并保持 `ascii_mode=false`（ASCII-OFF）。英文方案的“ASCII 关闭”表示让字母经过英文词库，而不是把它变成中文；ASCII-ON 会直接输入字符，跳过词库候选。

先输入一段英文单词的开头并查看候选。若没有候选，按顺序检查：当前方案 ID、ASCII 状态、英文词典及依赖是否齐全、部署是否成功，再检查补全参数。

薄荷公开的 `melt_eng` 默认将 `ascii_mode` 重置为关闭，正常时无需添加补丁。若自己改过默认状态或关闭了单词补全，可在同目录 `melt_eng.custom.yaml` 的现有 `patch` 中按需合并：

```yaml
patch:
  "switches/@0/reset": 0
  "translator/enable_completion": true
```

**上例的 `@0` 仅在实际生效的 `switches` 第一个项目是 `name: ascii_mode` 时适用**；默认薄荷英文方案如此，定制过顺序时要改为实际索引，不能直接照抄。`reset: 0` 设置方案初始化的默认状态，不保证立即改变当前会话。保存、重新部署并重新选择英文方案后再验证。

这里的补全是“输入部分字母出现单词候选”。选完一个单词后预测下一个单词，不是本皮肤已经提供的功能，需要输入法／方案另行支持。英文方案的词库覆盖范围也会影响候选结果。

### 3. 按需调整：气泡、Shift 与字号

在元书「键盘设置」检查这些项目：

| 设置项 | 使用建议 |
| --- | --- |
| 按键气泡 | 要看到普通点按／上滑气泡，保持开启；皮肤定义显示内容，开关由元书控制 |
| Shift 状态锁定 | 可保持你截图中的关闭状态；按个人习惯调整。它不是“英文句首自动大写”开关 |
| 候选文字 → 预编辑字符、候选字 | 本皮肤设定 12pt／16pt；如果实机仍不符合预期，可在元书中调整并看实际效果，不假定应用字号一定覆盖皮肤 |
| 内嵌输入模式 | 想在键盘上方显示并调整拼音预编辑时，使用非内嵌模式；截图中的预编辑字号设置注明仅关闭内嵌时有效 |
| 符号成对、双击空格输入句号 | 按个人偏好配置；若排查“多出字符”，可以先关闭相关自动输入行为，再核对皮肤的单个符号动作 |

原生气泡开关、字号设置与自动输入行为最终如何作用于自定义皮肤，仍需在元书中检查实际结果。

### 4. 原生长按时间与英文自动句首大写

皮肤没有已核实的原生长按延迟参数，不能把网页的 300ms 写成已经生效的元书设置。你提供的 1.11.0 设置截图及本次查阅的公开资料没有确认一个可用的延迟调节入口；如果本机版本确实提供此选项，再在元书中调整。没有入口时，按当前原生时间使用，不写入未证实兼容的旧版仓参数。

英文自动句首大写需要输入法自动改变 Shift 状态；本皮肤只显示并执行当前大小写。你提供的截图没有确认独立自动大写开关，不能把「Shift 状态锁定」当成它。若本机版本提供自动大写选项，可开启后在 `melt_eng` 中验证；否则当前可使用 Shift 手动输入大写。

### 5. 音节分隔、词库与重新部署

拼音／双拼中显示空格还是 `'` 分隔，由当前方案的分隔规则及预编辑格式共同决定。此前已选择保持薄荷原有格式，这里没有要求修改分隔符，也不让皮肤插入分隔字符；日后需要更改时，应针对正在使用的双拼或全拼方案配置。

自造词、用户词典与下一词联想也要在元书／方案侧处理。需要保存自造词等功能时，按元书要求检查第三方键盘的完全访问权限，皮肤入口不会代替权限配置。

修改「应用文件」里的方案后，要执行「重新部署」才能让键盘使用最新文件；不要只编辑生成的 `build` 产物，也不要把 `.custom.yaml` 放进皮肤目录。使用 iCloud 同步时，同时留意元书是否会从云端合并同名文件，避免旧文件覆盖修改。

完成设置后，检查冷启动、中英往返、英文候选、数字／符号返回，以及有／无预编辑时的符号输入。配置与网页检查不能替代这一步。
