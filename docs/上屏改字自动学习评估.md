# 上屏后改字自动学习：接口评估与局部实验

日期：2026-10-11（SGT）。目标：用户提供的元书 1.11.0(558)、Rime 1.17.0。Windows 实验使用小狼毫 0.17.4 中的 **librime 1.13.1**，不等同于手机引擎。没有执行元书实机验证。

## 结论

在当前已确认的公开配置接口下，**不能可靠完整实现「上屏后任意改字，自动学到最终结果」**。已实现并测试只读局部原型：对刚上屏后的末尾删除／重输，可以推算一个假设结果；由于缺少宿主文字、光标／选区确认和读音对应关系，原型一律返回 `learn_allowed: false`，不向正式用户词典写入。

这不是原生造词或普通词频学习失败。前三项继续工作：在同一次 Rime 预编辑里选完整词后上屏会造词；选词更新原生词频；Lua 上下文学习记录实际选中的接续词。任意宿主编辑需要另一条信息通路。

## 核对过的接口与方法

| 方法 | 能获得什么 | 缺少什么／结论 |
| --- | --- | --- |
| Rime Lua 通知、原始编码、候选与预编辑 | 本引擎的提交、按键、预编辑变化、原生候选资料 | 没有宿主选区、完整最终文本、输入框身份；不能作为完整编辑日志 |
| 本地影子文本与退格重放 | 在末尾且删除单位已知的假设下，组合已观察的提交 | 选择替换、触摸移动光标、外部修改会使假设失效；只保留为诊断原型 |
| 皮肤包围直接上屏／光标动作 | 知道本皮肤执行了某个动作，可及时取消联想、断开上下文 | 不等于知道动作后的实际光标／文字；系统选区操作不全经过皮肤 |
| 元书 JavaScript `$selectedText` 与静默脚本的 `$searchText` | 显式执行脚本时可获取选中文字或光标周边文字组合 | 文档未提供通用宿主编辑订阅，以及将最终文本和编码交给 Rime Lua 的直接桥接接口 |
| Lua `Memory` 用户词典接口 | 在已获得有效词条和编码时可以更新用户词典 | 能写词典不代表能可靠获得最终编辑结果；本轮没有猜测性写入 |

元书文档公开的通知包括 RIME 开关／方案、键盘动作、回车类型与预编辑变化；没有将宿主全文、选区和输入框身份作为持续编辑事件交给个人 Lua 的约定。`Context.caret_pos` 是编码串位置，不能当成宿主光标。

## 局部实验结果

`skin_edit_probe.lua` 只在新建隔离测试目录安装，显式开启后记录最多 256 个事件；不拦截按键、不插入文字、不调用词典写入接口。正式四份补丁没有挂载它，正常配套包也不包含它。正常 Rime 选词在测试数据库中的原生学习仍照常发生，与原型写入无关。

| 操作 | 结果 | 能否自动学词 |
| --- | --- | --- |
| 「哪个」→末尾退格两次→「那个」 | 真实 Rime 事件可以推算假设结果「那个」 | 拒绝：未确认宿主实际删除和最终文字 |
| 「库里姆」→末尾退格两次→「莉」→「姆」 | 真实事件可以推算假设结果「库莉姆」 | 拒绝：保留部分的原读音与改字对应关系未获得可靠确认 |
| 移动光标后删除「里」、输入「莉」 | 捕获方向键后标记为无法重建 | 不支持通用自动学习 |
| 在宿主选中「里」后输入「莉」 | Rime 提交日志可能只有「库里姆」「莉」，与在末尾追加「莉」相同 | 不支持：两种不同最终文本共享相同观察结果 |
| 连续末尾删除重输 | 单元实验可推算影子结果，但仍不确认宿主文字 | 不入库；真实多次编辑时序待手机确认 |
| 切换输入框、宿主外部改字 | 已知边界事件会让原型拒绝；当前接口不能保证提供全部边界 | 无法保证完整支持 |

原生实验在纯全拼诊断副本中关闭单字后的词语补全，并关闭上下文学习，以区分原型事件和正常联想；不修改正式方案。测试词仅加入隔离副本。

## 为什么不能从相同日志可靠推断

观察到的提交都是：先「库里姆」，后「莉」。如果宿主光标在末尾，结果可以是「库里姆莉」；如果宿主选中了中间的「里」，结果可以是「库莉姆」。普通 Rime 提交事件本身没有说明是哪一种情况。因此不能靠调大时间窗口、反向查拼音或增加更多词库消除这项歧义。

要完整实现，需要元书提供可验证的桥接数据：编辑前后的可用文本、实际光标／选区、稳定的输入框边界、删除／替换的实际结果，以及对应读音确认。若元书后续公开这些接口，可以继续只修改个人 Lua；当前没有据此修改 Rime 或元书源码。

现阶段采用可靠方法：在预编辑中整体造词，或用现有个人词库工具明确添加文字和读音。元书脚本获取文字可用于未来半自动入口研究，但本轮没有宣称已实现「选中文字一键入库」。
