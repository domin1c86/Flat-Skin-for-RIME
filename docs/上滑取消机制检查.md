# 上滑与长按滑选的取消机制检查

检查范围：仓库中的 light／dark 共 28 份生成配置、Jsonnet 按键源、网页 `preview/index.html`，以及删除全部验证版。没有元书键盘扩展源码，也未连接 iOS 实机。以下区分配置事实、文档约定与待验证行为，不把配置回归当作原生手势测试。

## 1. 直接上滑：宿主决定如何取消

`default/jsonnet/Keyboards/iPhonePinyin.libsonnet` 给每个主键盘字母配置 `swipeUpAction`，`hintStyle.swipeUpForegroundStyle` 只控制上滑时显示哪个符号。逗号、句号、空格、回车及其他布局的部分按键也有直接上滑动作；iPad 的部分按键使用上滑切换分体状态。

皮肤没有可执行的手指移动事件处理器，也没有已核实的「已上滑后下滑回撤」配置。`swipeDownAction` 表示另一个下滑动作，不代表取消之前的上滑，不能把它绑定为空动作就声称解决了取消问题。缺少宿主源码或实机证据时，既不能保证直接上滑可以取消，也不能断言它一定在识别瞬间执行。

## 2. 长按滑选：有无高亮的取消出口

字母三选气泡与英文逗号的候选开关使用 `hintSymbolsGridStyle`，与 `swipeUpAction` 是两条独立机制。根据元书网格文档：

- 手指松开时执行当前高亮项；没有高亮时不执行动作。
- 移到网格边界以外足够远，会清除高亮；移回后可以重新选择。
- 省略 `selected` 时初始没有高亮；回到起点附近、位移不超过 `moveThreshold` 时恢复初始状态。
- `anchor` 可以位于空单元格；空格不绘制、不可选中，只用于确定相对位移起点。

现有三选气泡与候选开关都有默认 `selected`。所以在这些气泡中，**滑回起点会恢复默认高亮，而不是取消**；应继续移远并确认高亮消失。它们并非没有取消权利，但不能给它们套用删除气泡的返回起点取消规则。旧版本回退使用单行 `hintSymbolsStyle`，也不能据网格参数保证其相同取消距离。

## 3. 删除气泡的本次调整

只有「删除全部」一个可见选项，其下方保留一个不可见的空锚点；不设置 `selected`，不绑定快速 `swipeUpAction`。只有选中后松手才请求删除。选中背景使用 `#D32F2F`，选中文字为 `#FFFFFF`；背景放在可见选项上，不绘制空锚点的背景。

纵向步进为 40pt，移动阈值为半步 20pt。用户长按后上滑到可见项，选中时红底白字；向下回到起按位置附近会恢复初始无高亮，松手不执行。这里是按起点计算位移，不是按上滑最远点计算固定回撤距离；精确命中范围、速度影响、过度滑动取消和再选中都需按元书实际行为验收。还需验证从起点只向下滑时不会误选上方的删除项。

为了支持文档允许的空锚点，构建校验器放宽了 `anchor` 的非空要求，但仍拒绝越界坐标、非整数坐标，以及指向空格的默认 `selected`。该修改不会改变正式皮肤产物。

## 4. 网页预览并不是手机实现

`preview/index.html` 的普通字母手势在 `pointerup` 中根据最终位移调用动作，显示上滑符号时并未立即输入。上滑后回到起点松手会落到普通点按分支，输入字母；因此不能把「没有输入上滑符号」误称为「取消所有输入」。

长按气泡则通过 `updateHold` 清除选中索引来取消：纵向移远超过 44 个演示单位时松手不输入内容。`pointercancel`、指针捕获丢失等也会清理手势。以上逻辑不运行在 iOS 元书内，本次未修改它来伪装手机支持。

## 5. 手机验收建议

在非重要输入框中，分别测试字母、逗号／句号、空格、回车以及数字页上有上滑动作的按键；区分「未达到长按时间的直接上滑」和「等气泡弹出后的滑选」。每次记录：上滑符号出现的时机、是否在松手前已发生输入、下滑后高亮是否消失、松手是否没有任何输入，以及回到起点是否意外输入原键。

删除气泡另需测试「上滑选中 → 下滑取消 → 松手」与「上滑选中 → 下滑取消 → 再次上滑选中 → 松手」。只有最后仍选中时才应执行一次。尚未验证的宿主行为不作通过结论。
