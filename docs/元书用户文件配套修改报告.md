## 2. 新增文件与每项修改

四份文件均位于 `external_files/oh-my-rime/` 根目录，与对应 `.schema.yaml` 同级。原来根目录没有这四份补丁，因此此次采用新增文件，不覆盖已有自定义内容。

| 文件 | 修改内容 |
| --- | --- |
| `double_pinyin_flypy.custom.yaml` | Shift／Caps 不再单键切换 ASCII；用于皮肤默认中文入口 |
| `rime_mint.custom.yaml` | 同上；用于全拼入口 |
| `rime_mint_flypy.custom.yaml` | 同上；用于小鹤混输入口 |
| `melt_eng.custom.yaml` | 同上，并启用补全、保留用户词典、关闭英文自动造句、禁用大写直通识别、接入已有英文大小写滤镜 |

### 四个方案共用的行为

```yaml
"ascii_composer/good_old_caps_lock": false
"ascii_composer/switch_key":
  Caps_Lock: noop
  Shift_L: noop
  Shift_R: noop
  Control_L: noop
  Control_R: noop
```

这组设置让中英切换主要通过皮肤按钮完成。它不禁用元书自己的 Shift 大小写显示，也不删除其他 RIME 快捷键。

**它也影响外接键盘：Shift／Caps 单键将不再切换 RIME 的 ASCII 模式。** 原生菜单或其他快捷键仍可能改变 ASCII 状态，皮肤布局不会因此自动跟随；发生错配时，用皮肤的中英按钮或方案面板重新选择。

### 独立英文方案追加的行为

```yaml
"switches/@0/reset": 0
"translator/enable_completion": true
"translator/enable_sentence": false
"translator/enable_user_dict": true
"recognizer/patterns/uppercase": "^$"
"engine/filters":
  - lua_filter@*autocap_filter
  - uniquifier
```

`@0` 已针对你这份文件核对为 `ascii_mode`；日后升级方案、调整开关顺序后要重新核对。`reset: 0` 是方案初始化默认值，不是持续强制关闭 ASCII 的命令。

大小写滤镜让普通英文候选跟随已输入的大小写，例如 `hello` → `hello`、`Hello` → `Hello`、`HELLO` → `HELLO`。它使用你已有的 Lua 文件，不新增新的滤镜源码。

**这不是“句首自动大写”。** 它不会在新句子开始时自动改变键盘 Shift，只处理已经输入了大写字母时的候选。原滤镜有意保留例外：单字母输入、含空格的词条、中文候选和部分缩写不会强制变换；大写转换后的用户词频学习也不作额外保证。

英文补全表示输入 `hel` 就有以这些字母开头的单词候选；不是选完一个单词后预测下一词。关闭自动造句也不关闭此单词补全。

## 3. 怎样与皮肤搭配使用

| 操作 | 布局与方案 |
| --- | --- |
| 中文键盘点击中英按钮 | 英文布局 + Easy English Nano（`melt_eng`） |
| 英文键盘点击中英按钮 | 中文布局 + 小鹤双拼－薄荷定制（`double_pinyin_flypy`） |
| 工具栏方案按钮选择全拼 | 中文布局 + `rime_mint` |
| 工具栏方案按钮选择小鹤混输 | 中文布局 + `rime_mint_flypy` |

英文返回中文仍固定为小鹤双拼，不会记忆上一次的全拼选择；此行为由当前皮肤定义，此次用户文件补丁没有改变它。

英文候选模式应保持 **ASCII-OFF**。在英文方案里，这表示使用英文词库，不表示输入中文。ASCII-ON 为直通，不会提供相同的词库候选。

中文普通点按继续进行双拼／全拼输入；独立英文普通点按使用英文词库。字母键上滑、长按符号使用皮肤的 `symbol` 动作直接输入；长按选择大小写字母也直接上屏，不进入词库。此次补丁没有把这些动作交给 RIME 标点转换。

中文中的英文混输、双拼编码、用户调频、简繁体、Emoji、反查、原音节分隔和预编辑格式保持原有配置。此前你已决定不修改音节分隔，所以没有加入撇号分隔补丁。

## 5. 手机上应用与回滚

1. 在元书确认正在使用的薄荷方案目录，备份该目录已有的同名 `.custom.yaml`（若手机上另有自定义内容）。
2. 将本次四份 `.custom.yaml` 放入「文件管理 → 应用文件 → RimeUserData → 当前薄荷方案目录」，与四份 schema 文件同级。不要放进皮肤目录、`build/` 或 `tools/Hamster/`。
3. 手机上已有同名补丁时，将本次条目合并到它原有的唯一 `patch:` 中，不整份覆盖用户其他配置，也不要添加第二个 `patch:`。此次交付基于你提供的备份。
4. 保留已有 `default.custom.yaml`；四个方案已经启用，不需要再改启用列表。
5. 执行元书「重新部署」，等待完成；有 iCloud 同步时留意旧同名文件覆盖。重新打开键盘并使用皮肤入口选择方案。
6. 若部署提示 `luna_pinyin` 缺失，先检查元书共享资源是否已提供它。备份中的笔画方案需要它；缺失时补齐兼容的明月拼音方案及其词典、依赖，再重新部署。不要删除现有用户数据库或依赖旧 `build` 缓存掩盖问题。

补丁附件 `dist/元书皮肤配套补丁.zip` 只包含四份补丁与本报告，**不是完整输入方案包**。解压后只将四份 YAML 放到既有目录；不要用它替换整个薄荷目录，也不要当成皮肤导入。

撤回此次修改时，删除此次新增的四份根目录补丁，或恢复手机上的原补丁，再重新部署。如果后来已经合并其他自定义内容，只撤回本报告列出的条目，不删除整个文件。用户词典数据库和原始 schema 不需要恢复。
