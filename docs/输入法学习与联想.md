# 薄荷的个人学习与联想

## 原生造词与个人词频

三个中文方案已经启用用户词典。它们使用同一份 `rime_mint` 用户词典，学习结果可在小鹤双拼、全拼和小鹤混输之间共享。无需开启按键纠错来造词。

输入完整编码，在同一次预编辑中依次选择目标字词，最后整体上屏，可以学到完整新词。例如在隔离测试中输入 `kulimu`，分选「库」「莉」「姆」后整体提交。这里只是测试例子，不预置到你的个人词库。

分两次上屏「库莉」和「姆」后，下一次也可能出现「库莉姆」，但可能仍是临时组句；候选类型 `sentence` 与已学词 `user_phrase` 不同。整体选中提交后才算完整造词。选择现有候选也会更新个人词频；不人为把「那个」固定置顶，因为「哪个」同样是正常词。

已上屏后在宿主输入框里改字，不等同于上述造词。用户词典的近期退格回滚受引擎事件、事务和时间窗口限制，手机上的删除未必全部经过这条链路。

原生验证：运行 `python scripts/check_rime_learning.py`。需要 Windows 小狼毫 0.17.4（本机 librime 1.13.1）、PyYAML 和 lupa；测试在新建的 `.tools/rime-learning-*` 目录部署，不复制个人数据库。测试字词及数据库不应导入手机。

元书实机检查：同一预编辑分段选词 → 整词上屏 → 重打编码；切换三个中文方案以及重启键盘后检查学习是否保留。Windows 引擎测试不能替代实机结果。


## 维护已有个人词库

入口就是已被主词典导入的 `dicts/custom_simple.dict.yaml`。没有另建空词库或覆盖旧词条；默认也不增加任何测试词。

在电脑上运行以下命令，将「新词」「xin ci」替换成自己的词语和无声调全拼（ü 写作 v）：

```shell
python scripts/manage_personal_dict.py add --text 新词 --code "xin ci" --dry-run
python scripts/manage_personal_dict.py add --text 新词 --code "xin ci" --weight 100
python scripts/manage_personal_dict.py update --text 新词 --code "xin ci" --weight 120
python scripts/manage_personal_dict.py remove --text 新词 --code "xin ci"
```

默认用户目录是本项目 `external_files/oh-my-rime`；使用 `--user-dir "实际方案目录"` 指定其他本地目录。更新读音时，先添加新编码条目，确认后删除旧编码条目。同词不同读音允许并存，同词同编码不允许重复。

每次真实修改前，在词库同目录 `.backups/` 保存原始字节备份；保留已有头部、注释、词条和换行。工具不操作用户词频数据库，也不会自动部署。将修改后的个人词库合并到手机实际方案目录后，在元书重新部署；手机另有新增词条时先合并，不能直接覆盖。回滚使用对应备份并重新部署。

## Lua 上下文学习

新增模块 `skin_context` 与三个组件包装文件，接入三个中文方案。它记录实际上屏的纯汉字文本之间的关联；候选重排沿用原 Candidate 对象，因此原生用户词典学习仍由 Rime 处理。用户词典与上下文数据库分开，上下文数据存放在当前用户目录的 `skin_context.userdb` 数据库，不要用它替换 `rime_mint.userdb`。

默认参数：前文有效期 30 秒，同一关联出现两次后生效，最多五个联想候选，自动接续一轮；每个前文最多保存二十个后续文本。排序仅在原候选前 32 项内调整同覆盖范围的中文候选，保留候选对象、编码和注释。不根据一次选词固定置顶同音词。

RIME 方案菜单新增「关联学习」和「联想」开关。关闭关联学习会停止记录、排序和预测并清空当前上下文；关闭联想仅关闭上屏后的候选，仍可学习和排序。开关在新引擎会话按方案默认值开启。数据库无法使用时退回原生输入。

空格关闭联想并输入实际空格；退格先关闭联想，不删除已上屏文字；点候选提交联想；继续打字结束联想并开始编码。非联想状态下，刚上屏后三秒内传到 Rime 的退格会撤销最近一次上下文关联写入，再交给原生处理。它不重建宿主文本，也不把局部改字当成完整新词。

验证：`python -m unittest discover -s tests -p test_context_learning.py -v` 和 `python scripts/check_context_native.py`。原生测试证明相同 `nage` 编码可在两个已学习前文下分别优先显示「哪个」和「那个」，以及预测、空格、删除、继续编码、跨方案与进程重启后的持久化。

## 安装新版皮肤与配套补丁

1. 备份手机当前方案中的四份同名补丁。解压 `dist/元书皮肤配套补丁.zip`，把四份 `.custom.yaml` 合并到已有的唯一 `patch:`，把 `lua/` 中五份 Lua 放入当前薄荷用户目录的 `lua/`。不要覆盖词库、用户数据库或整份方案目录。
2. 在元书重新部署。确认没有缺失 Lua 的错误。备份中原有笔画反查依赖 `luna_pinyin`；如果手机共享目录也未提供，应补齐该依赖，不能靠旧 build 缓存掩盖缺失。
3. 导入并启用新版 `dist/扁平灰白.cskin`。此次上下文联想需要皮肤与补丁一起更新；直接上屏动作的保护信号依赖新 Lua。英文只接收保护信号，不学习中文上下文。
4. 包内 `tools/manage_personal_dict.py` 供电脑使用，不需要复制到手机 `lua/`。在解压目录使用工具时，显式指定 `--user-dir "实际薄荷目录"`。词库没有预置新增条目。

皮肤在直接上屏、换页、方案切换等动作前发送 `Control+Shift+F9` 取消联想，再执行原动作，最后发送 `Control+Shift+F10` 中断上下文。普通字母与编码输入不加这组动作。联想时空格保持原空格键面与实际空格行为。信号不携带文字。

回滚时恢复旧皮肤和旧四份补丁并重新部署；新增 Lua 可以保留或删除。原生用户词典无需删除。仅清理上下文学习时，在键盘停止运行后备份并移走 `skin_context.userdb`，保留 `rime_mint.userdb`。

重新打包：`python scripts/build_skin.py`、`python scripts/build_rime_bundle.py`。符号审计和旧行为回归读取保护动作中间的原动作；另外的测试直接检查生成文件里的前后信号及执行次数，不把信号剥离后的结果当作全部验证。

## 上屏后改字评估

已完成接口核对、只读局部原型和隔离的真实 Rime 事件测试。末尾删除重输可以推算假设结果，但无法确认任意宿主编辑的最终文字；原型没有启用自动入库，也没有安装到正式配置。完整结论见 [上屏改字自动学习评估](上屏改字自动学习评估.md)。

当前上下文学习的可观测边界来自 Rime 和皮肤信号。直接在宿主触摸移动光标或切换输入框时，不能保证获得全部通知；需要在元书实机验证，不应将 30 秒内的所有连续提交都解释为同一输入框。
