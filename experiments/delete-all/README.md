# 删除全部 · 手机验证版

这是独立命名的实验皮肤，不替换正式版或六份留白皮肤。不修改 RIME 方案或个人词库，未绑定剪贴板读写动作。整个输入框能否清空尚未经过元书实机验证，不能把通过配置检查当作功能已经可用。

## 安装与操作

1. 使用元书商店版 **1.8.1 或更新版本**。长按网格需要 1.6.24 起支持，1.8.1 的官方日志另有 `#deleteText` 行为修复记录。
2. 通过文件或分享菜单用元书打开 `.cskin`，启用名称末尾带「删除全部验证」的皮肤。需要回退时直接选回原皮肤。
3. **仅在不重要的测试输入框内试用**，先复制保存有价值的内容。不要在密码框、真实聊天草稿或长文稿上首次测试；不保证可撤销。
4. 在中／英文主键盘上长按删除键，只出现一个「删除全部」气泡，初始没有选中项。保持按住并上滑，看到气泡变成**红底白字**后松手执行。仍未松手时向下滑回起按位置附近，红色高亮消失，此时松手不清空；只长按不移动也不清空。

气泡使用一项可见内容，上方是「删除全部」，下方是不可见的空锚点，不再显示「取消」按钮。上滑选择使用 40pt 的纵向步进；回到起按位置附近的 20pt 阈值内，按网格规则恢复初始的未选中状态。它不是「从最高点向下滑固定距离」的回撤识别；原生的具体边界、过度滑动和重新选中行为仍需实测。长按气泡浮出不代表已经清空，只有选中后松手才请求删除。

点按仍删除一个字符。为避免进入长按气泡前持续删字，**本验证版仅在主键盘移除了长按连删**；快速上滑没有绑定清空动作。数字页、符号页与 iPad 普通键盘不变；iPad 浮动键盘复用主键盘。若长按或取消时仍先删除了字符，请作为失败反馈，不要继续在重要内容中使用。

清空尝试依次执行：取消皮肤上下文预测、`#重输` 清除预编辑、`#deleteText` 请求宿主删除、重置皮肤上下文。`#deleteText` 的完整删除范围缺乏公开说明；尤其是光标右侧、多行及较长输入，需要下表实测。此版本不使用固定次数连续退格冒充清空。

## 验收表

先输入 `甲乙-ABC_123`，换行后输入 `第二行🙂!?`；每项测试前重新填写文本，记录元书版本、宿主 App、光标位置及剩余内容。

| 场景 | 通过标准 |
| --- | --- |
| 光标在末尾、开头、中间，分别执行清空 | 光标两侧及换行全部删除，不只是删除当前行或光标前文字 |
| 中英文、数字、符号、emoji、多行混合 | 当前输入框内无残留；其他输入框不受影响 |
| 已有文字，并且有未上屏拼音／英文候选 | 已上屏文字、预编辑及候选均清空，没有把候选意外上屏 |
| 空输入框、有选中文字 | 空框不报错；有选区时确认是否只删除选区，若是则不满足「删除全部」 |
| 长按不移动、上滑选中后下滑回原处、快速上滑 | 不执行清空；高亮消失时松手没有副作用，尤其检查是否先发生普通删除 |
| 长按后只向下滑动，从未上滑 | 不得误选「删除全部」，松手不得删除；不满足则验证失败 |
| 上滑选中、下滑取消、再次上滑选中后松手 | 只有最后仍为红底白字时执行一次，不因曾经选中过而强制执行 |
| 长文本、多个段落及不同宿主 App | 不残留后半段或其他段落；可先用备忘录和普通网页文本框 |
| 清空后继续输入、中英切换 | 正常输入，旧候选／预测不复活，不误触发送或换行 |
| 深浅色、横竖屏、小屏 | 气泡文字完整，选中与取消可辨，边缘不越界 |

只有上述关键场景实机通过，才考虑加入正式版本。若仅部分 App 可用，需明确兼容范围，不能宣称通用清空。

## 其他上滑功能的检查结果

需区分两条机制，不能把它们统称为同一种气泡：

- **直接上滑**：主键盘的 26 个字母、逗号／句号、空格、回车，以及数字页和 iPad 上的部分按键，使用 `swipeUpAction`。仓库只定义动作及气泡外观，真正的识别、执行时机和回撤由元书宿主控制；目前没有经过实机验证的「下滑取消已识别上滑」配置。因此不能承诺这些动作已经支持回撤，也不能仅凭配置断言它们一定强制执行。
- **长按后滑选**：主键盘字母三选、英文逗号的词库开关使用 `hintSymbolsGridStyle`。元书网格文档提供越界清除高亮、无高亮松手不执行的机制，不是必然强制执行。不过这些旧气泡设置了默认选中项，回到起点会重新选中默认项，不等于取消；应移到足够远、确认高亮消失再松手。删除气泡不设置默认选中项，所以滑回起点也能恢复未选中。
- **网页演示**：普通字母上滑在松手时依据最终位移执行，不是一触发就立即插入；但上滑后回到原位置再松手会走普通字母点按，所以也不算真正的「什么都不输入」。长按网格演示在纵向位移超过 44 个演示单位时清除高亮，松手取消。这仅是网页行为，不能当作手机证据。

本次未改变上述其他按键的动作，避免用未核实的参数覆盖手机原生手势。完整检查记录见项目 `docs/上滑取消机制检查.md`；希望直接上滑也具备统一取消手感时，需先实测宿主回撤行为，再判断是否改成长按网格路线。

## 重新构建

在项目根目录运行 `python scripts/build_delete_all_probe.py --jsonnet .tools/jsonnet.exe`，默认制作 0pt 留白验证版；可使用 `--padding 12` 制作指定宽度。此目录的 `main.jsonnet` 是构建模板，由脚本与正式入口一起放入临时目录编译，不能单独运行。

包内保留独立入口与 `main.standard.jsonnet`，手机端重新运行包内 `main.jsonnet` 仍保留验证功能。包中的静态 `demo.png` 沿用正式版，只展示底层键盘，不展示实验气泡。
